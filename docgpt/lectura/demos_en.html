Demo workshop: ten effects from palette cycling to rotozoom

Español · Start with the foundations

This expanded workshop lives in docgpt; the original C implementation remains in the repository's demos directory. Each lesson derives an algorithm, works through numbers, reviews limits and supplies an exercise with an answer.

Order Lesson Main idea
0 Foundations Buffers, phase, fixed point and timing
1 Cycle Palette permutation; pixel indices remain still
2 Scroll Circular rows split into two copies
3 Blinds Centred openings and intermediate arithmetic
4 Stripes Accumulated band positions and fixed velocities
5 Wobble Spatial density and temporal phase
6 Bounce Signed translation and clipping
7 Ripple Distance-based phase and attenuation
8 Mosaic Block sampling and reuse of unchanged results
9 Zoom Inverse sampling and a column table
10 Rotozoom Linear increments and visible intervals

Operation counts describe the algorithms, not benchmarks performed in this review. The foundations explain how to record reproducible timing measurements.

Player and resources

demos.h exposes demo_run() and demo_set_idle(). demos.c owns resources, selection, timing and transitions; demolib.h provides shared tables and services.

The player allocates two 64000-byte image buffers and a 768-byte palette, starts audio, loads each picture, presents it under black, fades in, runs an effect, fades out and advances. It finally closes audio, frees buffers and returns to text mode. Music comes from res/demo.wav.

There are seven external graphics functions and five audio functions. Graphics declarations are in demolib.h; audio declarations are in demos.c. A host port must provide all twelve with compatible signatures.

Playback differs from teaching order

Playback order is rotozoom, wobble, blinds, zoom, stripes, cycle, scroll, ripple, mosaic, bounce. Fifteen valid images therefore reuse the first five effects.

The default effect interval is 7 seconds, plus image loading and two 33-retrace fades. Fifteen images nominally take around two minutes at sustained 70 Hz. An image that cannot be opened is skipped without advancing the effect index.

Shared effect contract

int demo_name(unsigned char *image,
              unsigned char *screen,
              unsigned char *palette,
              unsigned long end_tick);

Preserve image, render into screen, return 1 after the interval or 0 on cancellation. Cycle deliberately edits the palette.

Most effects finish each iteration through demo_show(). Cycle presents initially, then directly services retrace, palette and demo_sound(). Fades also service audio and the host callback.

Run and extend

From Linux, with a previously built game:

./play.sh local -demo

From DOS, inside bin:

game.exe /demo

Individual effects are not separate executables. Experiment in a working copy. Adding one requires its source, declaration, include and table entry, plus object rules and response-file linkage in the root Makefile.

The game uses the idle callback for network service and remote ESC. Dynamic intro resources are released before world loading. Omitting -demo avoids those allocations and execution; linked code and static data still exist.

Workshop deliverable

Complete all ten exercises and create a variation. Supply its sampling formula, two hand-calculated frames, numeric limits, clipping rules and a description of what is precalculated.

Before the first effect: pixels, time and fixed point

Effect index · Español

This workshop supplies the vocabulary used by all ten effects. You need arrays and loops; no prior trigonometry is assumed.

1. Three separate resources

Each effect receives image, screen, palette and end_tick. image holds 64000 original colour indices and remains unchanged. screen is the writable result. palette contains 768 DAC-ready colour components. end_tick is the stopping time.

original image → transformation → screen → VGA
palette ────────────────────────────────→ DAC

Transforming the previous result repeatedly would accumulate rounding and lose detail. Geometric effects rebuild from image; cycle deliberately changes the palette instead.

Input BMPs must match the loader: 320 × 200, 8-bit indexed, uncompressed, 40-byte DIB, full palette, pixels at offset 1078. Their normal size is 65078 bytes. Index 0 must appear black because clipping uses it for the background.

2. Rows are memory spans

demo_row[y] stores y*320 as unsigned int; the last row starts at 63680. Signed 16-bit offsets cannot represent the whole screen.

memcpy copies a span and memset fills one with a byte. Find valid row, column and length before constructing pointers. A negative length converted to unsigned becomes a large memory operation, not an empty span.

3. Sine as a repeating height

Imagine the height of a point travelling around a wheel. It moves through the centre, top, centre, bottom and centre. Sine describes that smooth repeating motion.

One revolution here has 256 phases rather than 360 degrees:

Phase Revolution demo_sin
0 Start 0
64 Quarter 256
128 Half 0
192 Three quarters −256
256 Same as 0 0

Cosine is sine shifted by a quarter revolution, or 64 phases. The table contains integer approximations; neighbouring phases can share a value.

Amplitude sets the extent of movement. For ±24 pixels, calculate sine*24/256. Phase speed sets the increment per rendered frame. Adding 4 repeats after 64 frames; adding 3 repeats after 256. For a nonzero integer speed, the phase period is 256/gcd(256,speed), where gcd is the greatest common divisor. Zero speed holds the phase still.

4. Fixed point changes the unit

Store 1.5 as 1.5*256=384. The lowest eight bits express fractions of 1/256:

Real value Stored integer
0.5 128
1 256
1.5 384
2 512

Multiplying two scaled values produces a scale of 65536. Dividing by 256 restores the original scale: 384*512/256=768, representing 3. The intermediate product needs long. Widen operands before multiplication; assignment to a wide result afterwards is too late.

The source often uses >> 8 to reduce the scale. Right shifting a negative signed integer is implementation-defined in C; these routines target the arithmetic-shift behaviour of their Borland environment. A port must verify it. Not every quantity is a literal 16-bit 8.8 value: zoom and rotozoom accumulate coordinates in long, still with eight fractional bits.

5. Effect duration and animation rate differ

The BIOS clock runs at approximately 18.2 ticks per second. The current default is 7 seconds, converted to 7*182/10=127 ticks. Fade-in and fade-out each add 33 retraces.

Graphic phase advances per frame. A slow machine renders fewer frames during the same tick interval and therefore completes fewer revolutions. Retrace waiting limits presentation rate; it does not guarantee 70 frames per second.

6. End-of-frame services

The usual route is demo_show(screen): wait for retrace, copy 64000 bytes and call demo_sound(). That function services audio and the host callback. Cycle presents once, then handles retrace, DAC changes and demo_sound() directly.

Fades also service audio and the callback. Local ESC and a callback requesting cancellation share the cleanup path. Playing music does not make a long blocking calculation harmless: the current DMA half-buffer needs service approximately every 46.44 ms.

7. An effect skeleton

This fragment needs demolib.h and the player's linked functions; it is not a standalone executable:

int demo_example(unsigned char *image,
                 unsigned char *screen,
                 unsigned char *palette,
                 unsigned long end_tick)
{
    (void)palette;
    while (demo_now() < end_tick) {
        if (demo_escape_pressed() == 1) {
            return 0;
        }
        memcpy(screen, image, DEMO_SCREEN);
        demo_show(screen);
    }
    return 1;
}

Adding an effect requires a declaration, a table entry and its object in the root Makefile and link response file. Manually copied external declarations must match their definitions: a C linker does not guarantee detection of incompatible prototypes.

8. Experiments and measurements

Predict a single frame first, using a labelled grid. Change one parameter in a working copy and record the direction and magnitude of the result. Then observe the full sequence.

For timing comparisons, record hardware/emulator, version, core, cycles, image, duration, initial phase and audio state. Separate image generation, retrace waiting and VGA transfer. Historical host-CPU microseconds do not predict Turbo C performance on a 386.

The tutorials count operations to explain algorithmic cost; those counts are not newly executed benchmarks.

Exercise: sine=128 and amplitude=20. What displacement results? What period comes from adding 4 phases? Answer: 10 pixels and 64 frames.

cycle — Animate colours while pixels stay still

Español · Lesson 1 of 10 · Source · Shared foundations

What you will learn

Separate colour indices from RGB values, rotate whole palette entries and keep audio serviced when the image needs no reconstruction.

Start with four entries

A pixel containing 37 selects palette entry 37. Changing that entry changes every matching pixel without moving one byte of image data.

index       0       1       2       3
before      black   red     green   blue
after       black   green   blue    red
pixels      1 1 2 3 0 remain 1 1 2 3 0

The real effect rotates entries 1–255 and preserves entry 0 for black borders. A deliberately ordered colour ramp can suggest flowing water; an arbitrary photograph usually produces colour changes rather than coherent motion.

Follow four decisions in the source

  1. Copy image into screen and call demo_show() once.
  2. Wait for retrace and count frames.
  3. Every CYCLE_EVERY=3, save the first entry, move following entries down and place the saved one last.
  4. Write the palette and call demo_sound() for audio and the host callback.

Entries are three-byte BGR groups scaled to 0–63; the DAC writer emits RGB. Move all three components together. Rotating individual bytes would mix channels from different colours.

The forward loop reads the next entry before overwriting the current one. To reverse the rotation, save the last entry and traverse backwards.

Period and cost

The 255-entry permutation needs 255 rotations to return. At one rotation every three frames that is 765 frames, or about 10.93 seconds at a sustained 70 fps. The current seven-second effect interval normally ends before that. With CYCLE_EVERY=1, the nominal period is 3.64 seconds. Repeated colours can make the visible pattern repeat sooner.

After initial presentation, no further 64000-byte pixel copies are needed. Each rotation shifts 254 entries and restores one: 765 array bytes written, plus the small saved copy. The DAC function writes 768 colour components and selects the starting index; there are not 1024 colour components.

Limits and ownership

The palette remains rotated on exit. The player fades using its current contents, then loads the next image's palette. It does not secretly restore the original on ESC.

Changing CYCLE_FIRST to zero while keeping CYCLE_COUNT=255 includes black but excludes another entry. Keep the complete range consistent and ensure FIRST+COUNT <= 256.

Workshop with answer

Predict: movable palette [A,B,C,D], image indices [1,4,2]. After two left rotations, which colours appear?

Answer: palette [C,D,A,B], displayed colours [C,B,D].

Practice: use four labelled bands with consecutive indices and rotate only their entries. Colours should change while band positions and widths remain fixed. A changing black background indicates a wrong range; unrelated channel changes suggest a wrong three-byte step.

Extension: design separate water and light ramps with independent counters. Explain why both animations still require no pixel movement.

scroll — Move an image with two row copies

Español · Lesson 2 of 10 · Source · Shared foundations

What you will learn

Turn circular movement into contiguous spans and distinguish visible movement from the direction of source sampling.

original:    A B C D E F G H
shift right: 3
result:      F G H A B C D E

copy source [0,5) to destination [3,8)
copy source [5,8) to destination [0,3)

The destination spans do not overlap and cover the row. No per-pixel modulo is required.

Generalise to 320 pixels

For offset_x in 0–319:

memcpy(screen + destination_row + offset_x,
       image + source_row,
       DEMO_WIDTH - offset_x);
memcpy(screen + destination_row,
       image + source_row + DEMO_WIDTH - offset_x,
       offset_x);

The first copy moves the beginning right; the second wraps the end around to the left. At offset zero, the second copy has zero length, which is valid in this use.

Vertical sampling reverses the visible direction

Source row is y+offset_y, subtracting 200 when necessary. Both operands are in 0–199, so the sum is at most 398 and one subtraction suffices.

With offset_y=1, screen row zero reads original row one: the picture moves up. Increasing X moves it right. The current diagonal is right and up, as determined by the actual copies.

Each frame selects a source row, performs the two horizontal copies for all 200 rows, presents and services audio. X advances every frame; Y advances every third frame.

Wrapping and period

The source resets offsets to zero after crossing the limit. That works with its current unit increments. For arbitrary larger speeds it can lose a remainder: 319+3 should wrap to 2 rather than 0.

X repeats after 320 frames; Y including its counter repeats after 600. Their combined state repeats after 4800 frames, about 68.57 seconds at 70 fps. With vertical movement every frame, the combined period would be 1600 frames.

Cost and diagnostics

There are 400 row-copy calls covering 64000 bytes, followed by another 64000-byte VGA transfer in demo_show. The exact machine instructions used by memcpy depend on compiler, library and memory model.

Removing the second copy leaves previous buffer contents in the missing region; those contents are not necessarily black. Unexpected diagonal lines suggest a stride error. A discontinuity at larger speeds suggests a discarded wrap remainder.

Workshop with answer

Predict: ABCDEFGH shifted right by 7. Answer: BCDEFGHA, equivalent to one step left.

Practice: use numbered rows and a horizontal arrow. Freeze Y to establish horizontal direction; freeze X to establish vertical direction. Then enable both.

Extension: support negative speeds. Prove offsets are in range before pointer arithmetic and that the two copy lengths always sum to 320.

blinds — Derive a centred opening

Español · Lesson 3 of 10 · Source · Shared foundations

What you will learn

Map a sine value to a width, share one calculation across several rows and audit intermediate arithmetic on Turbo C.

Actual source discrepancy: the product computing half can overflow a signed 16-bit int. The widened formula below is an educational correction; the original C file remains unchanged.

One opening, three spans

The screen contains 20 strips of 10 rows. Each reveals a centred window while covering both sides with black. Source pixels keep their original positions.

half is half the visible width. Each black border is 160-half pixels and the visible span is 2*half. Their sum is always 320.

Sine Sine + 256 Mathematical product ×160 Half Visible width
−256 0 0 0 0
0 256 40960 80 160
256 512 81920 160 320

Both 40960 and 81920 exceed signed 16-bit range. Dividing or clamping afterwards does not repair prior overflow. Widen before multiplying:

half = (int)(((long)(demo_sin(phase + slat * BLINDS_STAGGER)
                    + DEMO_ONE) * (DEMO_WIDTH / 2))
             / (DEMO_ONE * 2L));

With correct arithmetic and the existing table, this maps exactly into 0–160. Clamping provides additional protection when parameters change; it is not an overflow remedy.

From one strip to twenty

A strip samples phase + slat*6. Neighbours use nearby points on the same wave. Phase advances by 3 per frame and repeats after 256 frames. Setting the stagger to zero makes all strips open together.

For every row:

fill [0,160-half) black
copy [160-half,160+half) from the identical source position
fill [160+half,320) black

At full opening, both fills have zero length; at full closure, the copy has zero length. No negative length is valid.

Cost and strip limits

One frame uses 20 sine lookups and 200 × (two fills + one copy). Those spans write 64000 buffer bytes in total, followed by presentation.

The current loops require BLINDS_SLAT to divide 200. Height 11 leaves two rows untouched. Height 4 produces 50 strips, not 40. Arbitrary strip heights require clipping the final strip.

Workshop with answer

Predict: sine=128. Answer: half=120, visible width=240 and 40 black pixels on either side.

Practice: freeze the phase in a working copy and verify minimum, zero and maximum sine using the widened calculation. Then enable animation and finally strip staggering. This separates arithmetic errors from motion errors.

Extension: open from the left instead of the centre. Prove that the visible and black spans still cover exactly 320 pixels.

stripes — Give each band its own velocity

Español · Lesson 4 of 10 · Source · Shared foundations

What you will learn

Distinguish accumulated position from velocity, assign a table-driven pattern and prove that wrapping preserves bounds.

Scroll has one horizontal offset. Stripes has 25 offsets, one per eight-row band. Each band uses the same two circular row copies but advances at its own speed:

next offset = current offset + velocity
band velocity = sine(band*11) * 6 / 256

The source uses arithmetic >> 8; review negative signed-shift behaviour when porting. Velocities are constant during this effect, even though the loop recomputes them. Positions may realign; velocities do not gradually become equal.

Work through the table

Band Phase Table sine Resulting velocity
0 0 0 0
1 11 68 1
2 22 132 3
3 33 185 4
4 44 226 5

Band zero stays still; the sequence does not begin at +6.

Prove the wrap

while (offset[stripe] < 0) {
    offset[stripe] = offset[stripe] + DEMO_WIDTH;
}
while (offset[stripe] >= DEMO_WIDTH) {
    offset[stripe] = offset[stripe] - DEMO_WIDTH;
}

Previous offsets lie in 0–319 and current speeds in −6..6, so candidates lie in −6..325. At most one correction is needed with these constants. The loops support larger changes; they are not necessary merely because many frames have elapsed. Every frame restores the invariant.

Examples: 318+4 wraps to 2; 1−3 wraps to 318.

Why a phase spacing of 11?

11 is coprime with 256, so sufficiently many steps visit all phases before repeating. A spacing of 64 visits only four. Coprimality matters, not primality by itself. With 25 bands, only part of that phase sequence is sampled.

Cost and limits

Each frame performs 400 span copies covering 64000 buffer bytes, plus 25 sine lookups and offset updates. Fixed velocities could be precalculated once; the current implementation calculates them in the loop.

Band height must divide 200 with the current loops, or the final partial band needs explicit clipping. Increasing speed amplitude also requires checking the intermediate sine product against 16-bit limits.

Workshop with answer

Predict: velocity 5, initial offset 0, ten updates. Answer: offset 50; velocity remains 5.

Practice: change phase spacing to 64 and predict the repeated speeds: 0,+6,0,−6. Use an image with labelled bands to verify them.

Extension: add a time-varying phase to the sine. Velocity now changes and can reverse. Explain how accumulating that velocity differs from wobble's direct calculation of an oscillating position.

wobble — Give each row an oscillating position

Español · Lesson 5 of 10 · Source · Shared foundations

What you will learn

Separate wave amplitude, spatial density and temporal speed while reusing scroll's two-copy row renderer.

shift(y,t) = sine(phase(t) + y*density) * amplitude /256
amplitude =24
density =3 phases per row
next phase =phase+4

Amplitude controls horizontal range. Density controls variation between rows. Speed controls variation between frames. Unlike stripes, wobble computes the complete displacement directly; it does not accumulate a velocity into a row position.

Calculate one frame

Temporarily use density 1 and phase 0 to isolate the arithmetic:

Row Sampled phase Sine Shift
0 0 0 0
64 64 256 +24
128 128 0 0
192 192 −256 −24

At the actual density 3, continuous wavelength is 256/3≈85.33 rows, or about 2.34 cycles across 200 rows. Density 1 shows less than one full cycle vertically.

Adding 4 to phase repeats after 64 frames, about 0.91 seconds at sustained 70 fps. Quantisation may repeat particular shifts sooner, but the phase period remains 64.

Convert negative shifts to circular offsets

Two-copy rendering expects 0–319. Shift−5 is equivalent to+315 for a 320-pixel circular row:

if (shift < 0) {
    shift = shift + DEMO_WIDTH;
}

At amplitude 24, one addition is sufficient. Larger amplitudes require checking both the wrapping range and the earlier multiplication.

Two independent numeric limits

The sine product reaches 6144 at amplitude 24 and 20480 at amplitude 80; both fit signed 16-bit arithmetic. At amplitude 128 it can reach 32768 and overflow. Being smaller than the screen width does not make the product safe.

Widening the product to long enables further experiments, but offsets still need correct normalisation before the two copies.

Cost and a useful control experiment

Each frame uses 200 sine lookups,200 shifts and 400 span copies covering 64000 bytes. demo_show adds VGA presentation and audio service.

Remove Y from the sine phase and every row moves equally: the result is a horizontal oscillating translation. This demonstrates that spatial dependence creates the wave, rather than the mere presence of a sine function.

Workshop with answer

Predict: amplitude 24, sine−128. Answer: shift−12, wrapped offset 308; the row moves 12 pixels left.

Practice: independently try amplitude 24→48, density 3→1 and speed 4→2. Expect twice the range, a longer wave and twice as many frames per period. Restore each parameter before changing the next.

Extension: vary amplitude from zero at the top to 24 at the bottom. This prepares ripple's spatial attenuation; widen intermediate products when the new ranges require it.

bounce — Translate an image and clip its edges

Español · Lesson 6 of 10 · Source · Shared foundations

What you will learn

Apply sprite clipping to a full image and distinguish a calculated trajectory from simulated physical bounces.

The source does not collide with walls and reverse velocity. It directly computes:

offset_x = sine(angle_x)*90/256
offset_y = cosine(angle_y)*60/256
angle_x advances by 3; angle_y by 5

The initial offset is (0,60): the picture begins 60 pixels down. Both phases repeat together after 256 frames, about 3.66 seconds at 70 fps. The path is a discrete Lissajous trajectory with a definite short period.

Translate without wrapping

Unlike scroll, departing pixels do not reappear at the opposite edge. Clear screen to black, then copy the visible intersection.

For screen row Y, use source_y=y-offset_y. If it is outside 0–199, leave the row black. At vertical offset 20, screen row 20 reads source row 0 and the first 20 rows stay black.

X offset Destination start Source start Width
+30 30 0 290
0 0 0 320
−30 0 30 290

Keep positions signed while finding those spans. Construct pointers and convert offsets only after validating the source row and positive copy width.

Numeric limits and trajectory changes

The current sine products reach 23040 and 15360, fitting signed 16-bit arithmetic. An amplitude of 200 reaches 51200 and requires widening before multiplication. The later copy_width <= 0 guard cannot repair prior overflow.

Setting both phase speeds to 4 produces an ellipse, because X uses sine and Y uses cosine. It does not produce a diagonal. Using sine on both axes with identical phases would produce a straight-line path.

Cost

Each frame clears 64000 bytes and copies up to 200 visible row spans. Offset (30,20) copies 290*180=52200 additional bytes before VGA presentation. Only two sine/cosine lookups are needed; most work is memory movement.

Workshop with answer

Predict: offset (−12,7). Answer: source X=12..319 and Y=0..192; destination X=0..307 and Y=7..199. The visible rectangle is 308 ×193, with black above and on the right.

Practice: freeze motion and test (0,0), (30,20) and (−30,−20) in a working copy. Grid lines should remain straight without stretching or wrapping.

Extension: replace the phase model with position and velocity reversed at limits. That would simulate bounces; describe its additional state and different trajectory.

ripple — Let a wave weaken towards the edges

Español · Lesson 7 of 10 · Source · Shared foundations

What you will learn

Use distance from a centre line and an amplitude envelope. This is a row deformation, not a two-dimensional circular water simulation.

distance = abs(y-100)
amplitude = 20*(100-distance)/100
shift = sine(phase + distance*4)*amplitude/256

Rows 50 and 150 have the same distance, amplitude and phase, so they shift equally. Amplitude is the maximum possible displacement, not the current displacement itself.

Build the envelope

Row Distance Integer amplitude
0 100 0
25 75 5
50 50 10
100 0 20
150 50 10
199 99 0

The final row reaches zero through integer truncation. The centre line is 100 while row indices run 0–199, so the two boundaries are not perfectly symmetric.

Without attenuation, the edges would move as strongly as the centre. This would still differ from ordinary wobble because phase depends on absolute distance rather than Y directly.

Derive propagation direction

Phase advances by−5. Following a crest means keeping phase+4*distance approximately constant. A phase decrease of 5 requires distance to increase by 1.25, so the crest moves outward. Reversing speed to+5 moves it inward.

This reasoning describes an ideal continuous pattern; rows and integer samples quantise it. The spatial wavelength is 64 rows of distance. Temporal phase repeats after 256 frames.

Render and count the work

Displacement stays in−20..20. Add 320 to a negative value and perform scroll's two circular copies. A zero-amplitude row copies unchanged.

Attenuation adds one multiplication and one division per row; displacement adds another product and scale reduction. A frame uses 200 sine lookups and 400 span copies covering 64000 bytes, followed by presentation.

Larger amplitudes require reviewing signed 16-bit products and the one-addition wrap assumption. A quadratic envelope is a visual design choice, not automatically a more physically accurate model.

Workshop with answer

Predict: row 50, sampled sine 128. Answer: distance 50, amplitude 10, displacement 5. Row 150 produces the same displacement.

Practice: use vertical grid lines. Compare speeds−5 and+5, then remove attenuation alone. Distinguish reversing travel from strengthening edge motion.

Extension: propose a truly circular wave. Its distance would depend on both X and Y, requiring per-pixel sampling rather than two row copies. Explain the extra work before implementing it.

mosaic — One sample colours an entire block

Español · Lesson 8 of 10 · Source · Shared foundations

What you will learn

Rebuild an image by regions, clip partial blocks and recognise when an unchanged result can be reused.

Each block takes its top-left pixel:

A B C D      A A A A
E F G H  →   A A A A
I J K L      A A A A
M N O P      A A A A

This is sampling, not averaging. Averaging palette indices does not generally average their colours.

Size from phase

block=1+(sine(phase)+256)*39/512 produces 1 at minimum sine,20 at zero and 40 at maximum. Initial phase is zero, so the effect starts at block 20. Phase advances by 2 and repeats after 128 frames.

The initial 1 prevents a zero step in the block loops. The present maximum intermediate product is 19968, within signed 16-bit range.

Render partial rectangles

At each block origin, use width=min(block,320-x) and height=min(block,200-y). Read one source pixel and fill the resulting rectangle row by row.

Block 30 produces 11 ×7 blocks with partial widths/heights of 20 at the edges. Block 40 produces 8 ×5 complete blocks. Partial edge blocks are explicitly supported.

Cache an identical result

last_block=-1 forces the first rebuild. If the size repeats, the image and sampling grid are unchanged, so reuse screen while still presenting and servicing audio. If another parameter changed the sampled result, block size alone would no longer be a valid cache key.

The actual table sampled every second phase yields 78 size transitions and 50 repeated sizes in a closed 128-frame cycle: approximately 39.1% of reconstructions can be skipped, not 93%. Startup forces a first draw and partial intervals have different proportions.

Block 1 has a separate identity optimisation: one 64000-byte copy replaces 64000 one-byte fills.

Cost and bounds

A rebuilt frame with B>1 reads ceil(320/B)*ceil(200/B) samples and performs ceil(320/B)*200 row fills, covering 64000 bytes. At B=40 this means 40 samples and 1600 fills.

Changing the maximum to 100 makes the intermediate product 50688 and requires long before multiplication. It would create 4 ×2=8 blocks, not four.

Workshop with answer

Predict: B=17, last origin (306,187). Answer: width 14, height 13,182 output pixels from one sample.

Practice: freeze sizes 1,20,30 and 40. Verify identity, block counts and trimmed edges, then enable the sine and count size transitions.

Extension: use independently sized rectangular blocks. Both dimensions must be part of the reuse decision.

zoom — Find the source of every screen pixel

Español · Lesson 9 of 10 · Source · Shared foundations

What you will learn

Inverse sampling, centred scaling and a reusable column table.

Pushing each source pixel to one enlarged destination position leaves holes. Inverse sampling visits each destination and asks which source position it should read.

source step0.5: 0 0 1 1 2 2 → repeated samples, larger image
source step1:   0 1 2 3 4 5 → identity
source step2:   0 2 4 6 8...→ skipped samples, smaller image

The scale variable is an inverse sampling step. Larger values shrink the displayed image; ideal magnification is 1/step.

Keep the centre fixed

For centre (160,100) and real step S:

u=160+(x-160)*S
v=100+(y-100)*S

Fixed-point step 256 represents 1. The source corner is computed in long as (160<<8)-step*160, and similarly for Y. Add step for each destination column/row.

Step 256 yields identity. Step 128 begins at source (80,50) and doubles the central image. At step 512, u=2*x-160 and v=2*y-100: valid destination columns are 80..239 and rows 50..149. The visible image is 160 ×100 with black outside.

Reuse horizontal answers

Without rotation, source X depends only on destination X. A 320-entry unsigned int table costs 640 bytes and supplies the same source columns for every row:

for (x = first; x <= last; x++) {
    screen[destination + x] = image[source_row + column[x]];
}

Precalculation also discovers first/last valid columns. Invalid entries are never consumed. Entire invalid rows are filled black; valid rows combine black borders with sampled pixels.

The unsigned comparison rejects negative and excessive source coordinates before indexing. It does not make an invalid coordinate safe to use as a pointer.

Exact constants and limits

The midpoint is 358 and amplitude 204, giving fixed-point steps 154..562, approximately 0.60156..2.19531. These are sampling steps, not direct magnification factors.

The minimum-step clamp avoids visual degeneracy. A zero step would sample the same central coordinate everywhere; this sampler would not divide by zero.

Cost and image quality

The table requires 320 horizontal transformations per frame, followed by up to 64000 visible samples and black fills. It removes repeated horizontal arithmetic, not screen writes.

There is no filtering. Thin lines can disappear during reduction; averaging colours would need more work and a method for mapping results back to palette indices.

Practice: disable breathing amplitude and test steps 256,128 and 512: identity, doubled centre and 160 ×100 reduction. Use a grid to expose centre and clipping errors.

DEMO WORKSHOP / STUDY EDITION

rotozoom — Rotation, scaling and one visible span per row

Español · Lesson 10 of 10 · Source · Shared foundations

What you will learn

Build a transform from two directions, replace repeated products with increments and solve valid intervals before sampling pixels. Complete zoom first.

Derive signs from the implementation

With centre (160,100), sine s, cosine c and inverse step S:

u=160+S*(c*(x-160)-s*(y-100))
v=100+S*(s*(x-160)+c*(y-100))

These signs match the executed increments du_dy=-dv_dx, dv_dy=du_dx. The original introductory source comment shows different signs. Inverse sampling also means the visible image rotation is inverse to the destination-to-source coordinate rotation; remember that screen Y increases downward.

du_dx = ((long)demo_cos(angle) * scale) >> DEMO_SHIFT;
dv_dx = ((long)demo_sin(angle) * scale) >> DEMO_SHIFT;
du_dy = -dv_dx;
dv_dy = du_dx;

Subtract 160 horizontal increments and 100 vertical increments from the source centre to obtain the source corner. Advance U/V by the horizontal increments per pixel and the row origin by the vertical increments per row.

This removes four products per pixel from direct evaluation. Sampling still requires coordinate conversion, memory reads/writes and row lookup; two additions are the coordinate update, not the entire pixel cost.

Check two orientations

At scale 256 and phase 0, U=X and V=Y: identity. At scale 256 and phase 64, u=260-y, v=x-60; destination (170,100) reads source (160,110). The centre remains fixed.

Scale ranges 128..512, representing inverse steps 0.5..2. Rotation phase advances 2 and breathing phase 1; their combined phase state repeats after 256 frames.

Solve the visible interval

For each source coordinate, rotozoom_span solves:

0 <= start+x*step < limit

All quantities use fixed point; U's limit is 320256 and V's is 200256. The strict upper bound explains limit-1 in integer formulas.

For positive step, take start−5, step 3 and limit 10. Values are−5,−2,1,4,7,10, so valid X is 2..4. The lower bound uses ceiling division (5+3-1)/3=2; the upper bound uses (10-1+5)/3=4.

For negative step, take start 14, step−3 and limit 10:14,11,8,5,2,−1, again yielding 2..4. The implementation changes sign to divide nonnegative quantities, avoiding C 89's negative-division rounding variation.

For step 0, either start is valid and the whole row qualifies, or no X qualifies. This explicit branch avoids division by zero. Zero scale would be a visual degeneracy, not an inevitable division failure.

Intersect both coordinates

If U allows 2..8 and V allows 5..11, keep 5..8. Take the larger first endpoint and smaller last endpoint, then restrict to screen columns 0..319. Empty intersections become black rows; otherwise fill the borders and sample the interior.

Both source coordinates must be valid. The single-span property follows from convexity; it is not true for arbitrary nonconvex shapes or nonlinear per-pixel deformations.

Cost and pitfalls

There are frame-level increments, up to two span calculations per row and samples only inside the valid region. Zoom's single column table does not generally apply because source U changes between rows.

Changing du_dy to positive dv_dx is not always a mirror: it changes the matrix and may shear or become singular. When sine equals cosine, its two directions coincide.
